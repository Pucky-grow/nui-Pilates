# 小程序管理员工作台交付

本次按确认的计划，将小程序管理入口补齐为日常业务工作台。仅在自行创建的隔离 MySQL 8.0.46 / Redis 7.4.10 验证；未操作真实业务库、发布小程序、部署、发送真实通知或调用真实支付。

## 操作入口

微信开发者工具重新编译 → 登录页「教练 / 员工登录」→ 管理员账号 → 管理工作台。管理员登录态可恢复；退出或账号切换清理会员、教练和管理员身份。账号停用、登录过期和权限撤销由服务端逐请求判定，前端不自动替换为会员身份。

- **会员管理**：按会员号、昵称、手机搜索和分页；编辑昵称、头像、联系方式、性别、等级、有效期、状态；查看预约与上课记录。停用会阻止继续登录和预约。会员的微信身份标识、累计消费和累计上课次数不接受表单修改。
- **预约管理**：按会员、课程名称、预约编号、手机号、上课日期和状态查找；查看排课关联名单；代预约、取消、调整到其他排课、签到窗口内代签到。写操作仅 ADMIN，可填写训练目标并必须记录操作原因。
- **课程管理**：按名称查询和分页，直接按 ID 加载详情，新增/编辑课程完整资料，上下架、分类维护、授课资格指派/停用/恢复。
- **排课管理**：按日、课程、教练、状态查询；创建单次排课；修改、容量调整、整节取消及预约名单。选择名称，不要求输入数据库 ID。已有任何预约历史时，课程/教练/教室/时间锁定，只允许改容量；整节取消需原因。
- **教练与教室**：维护教练档案、状态和教室资料、设备、容量、状态。存在待开课排课时不能直接停用关联资源；教室缩容不能低于关联待开课排课容量。关联排课历史阻止直接删除课程/教练。
- **审核**：复用现有课程审核、请假与调课审批；冲突和已有预约历史限制仍在服务端生效。
- **门店与首页**：复用门店信息、Banner、热门课程、首页教练团队页面；统一认证、错误处理与加载状态。
- **规则与记录**：ADMIN 可以维护提前开放天数、预约截止分钟、每日上限、免费取消小时和历史课包模式晚取消参数；FREE 模式不开放切换。签到窗口仍固定为开课前30分钟至结束前，明确只读展示。操作记录包含操作者、目标、原因、结果及关键变更前后值；会员电话在变更快照中脱敏。

课包销售、支付退款、候补、周期排课界面不在本次新增范围。保留现有历史查询及处理能力。菜单按现有权限显示；店长沿用现有业务权限，前台仍使用 Web，教练继续受本人授课范围限制。没有给 STAFF、COACH 或 STORE_MANAGER 自动新增授权。

## 一致性及实现

| 变化 | 文件/机制 | 验证 |
|---|---|---|
| 多排课原子调整 | BookingService.move、ScheduleExecution.runMany；统一排序取得会员及两节课锁，再开启事务，提交后校准两节课 Redis | 并发调整同一旧 ID 仅一个成功；满班/每日限额失败保留原预约及库存 |
| 预约管理接口 | AdminBookingController，独立管理命名空间；member:view 查询，ADMIN 角色及 booking:manage 双校验写入 | 真实 HTTP 验证管理、店长、前台、教练及会员边界；历史 ID 不能处理新预约 |
| 会员查询与编辑 | MemberMapper.search 先筛选再分页；AdminMemberController 白名单、事务及安全资料视图 | 超过一页的搜索无漏查；无 openid/unionid 泄漏；非法字段/状态回滚，停用旧登录失效 |
| 课程/教室及详情入口 | CourseAdminService、CourseAdminController、ScheduleAdminController；资源锁、关联检查、DTO 校验 | 全流程新建与容量调整、整节取消、非法参数拒绝 |
| 规则、工作台和日志 | AdminWorkspaceController；规则白名单、事务提交后清缓存；OpLogAspect 固定字段快照 | 非管理员拒绝；小数、布尔值、未知规则拒绝；旧缓存更新；FREE 不变 |
| 小程序页面与表单 | admin 各管理页、common.js、api.js、management-form 组件及 app.json | Node 页面/请求测试，WXML/WXSS 原生编译、JS/JSON 检查 |
| 登录及网络错误 | pages/login、utils/request、admin/api | 账号切换、401 退出、网络 errMsg 保留、空服务地址不发请求 |

调整预约不重写旧记录的 scheduleId：原记录取消，新记录使用新 bookingId。旧请求重试只能命中历史记录。任何取消/签到/排课修改都保留原容量、每日限额、资格、时间和状态规则。SIGNED_IN、COMPLETED、NO_SHOW 与 BOOKED 一起计占位；取消/退款/逻辑删除释放占位。

规则缓存是数据库优先的现有60秒缓存。正常提交后立即清除相应键；Redis 删除失败时最多等待原缓存 TTL，不能把成功的数据库提交报告为回滚。新预约等写操作的库存同步失败仍沿用 Round3 的删除可疑键和下一次操作/定时对账机制。本地联调关闭定时任务，需要时通过既有对账入口操作专属实例。

## 验证结果及范围

详见 `admin-workspace-verification.json`，区分后端真实 HTTP、前端 VM 测试、原生模板编译和设备人工验收；重复执行的测试不重复累计。

最终通过：54个不重复后端方法（其中13个管理端真实 HTTP 方法）、34项小程序 Node 测试、25份 WXML 和26份 WXSS 原生编译，以及77份 JS/69份 JSON 静态检查。本机新版本后端登录及12个在线请求检查通过。文件数量不计作业务测试数量。

完整回归复用 RoundOneConsistencyTest、Round3AcceptanceTest、SchedulingAndFreeFlowTest、MemberHttpBoundaryTest；新增 AdminWorkspaceTest。最后新增输入校验和课程关键字查询后仅补跑管理端相关测试。完整回归和补充回归的同名方法按最新结果去重。

测试准备中修正了随机账号长度超过数据库上限，以及旧测试临近午夜时把次日时间放在当日的问题；没有放宽生产校验。原生 WXML 编译还发现并修正了表达式中的 HTML 实体写法；全项目 JS 检查发现并修正分类表单的引号错误。

以下内容仍待人工执行：微信开发者工具管理页实际操作、iOS/Android 真机、真实微信认证、手机可访问的隔离 HTTPS 服务及合法域名。模板编译器检查不代表设备验收。本机 127.0.0.1:8090 不能直接供另一部手机访问。

```sh
  --mysql-bin /tmp/pilates-round3-tools/mysql-8.0.46-macos15-arm64/bin \
  --output-directory /tmp/pilates-admin-review \
  --report-file admin-workspace-verification.json --skip-processes \

```

独立证据目录避免覆盖 Round3 的历史报告。运行器自行创建和销毁数据库/Redis，拒绝现有数据库 URL。本次未重跑双 OS 进程并发；以前的双实例证据不能代替新预约调整的多实例验收，本次适用范围为单后端实例内受控并发及共享分布式锁实现。

常驻联调后端：`python3 scripts/dev-local.py start|status|stop`。更改代码后先 stop 再 start，数据库保留。启动器与验收运行器使用不同专属实例。

## 应用升级和回退

本次没有新增表、字段、索引或自动授权迁移。前置数据库必须已经具备 Round2 有效预约索引和 Round3 兼容修正。先审核本次代码和回归证据，再在隔离环境更新后端及小程序；旧小程序仍可调用原接口，新工作台要求新后端。已存在的 Round3 业务环境升级前置条件继续适用。

业务环境操作仍需按 ROUND3-UPGRADE-RUNBOOK.md 完成只读预检查、备份及恢复验证、停写和停止旧实例/任务，再安排应用更新；本次没有执行。新工作台必须使用相应环境 HTTPS 地址，不能携带本机 Mock 配置发布。

回退本次应用时保留预约、取消、签到和操作日志；新增代预约/调整记录仍属于原有状态机和有效预约索引。退回兼容 Round3 的后端可继续处理这些记录，但新页面/新接口需要同步回退。不重建旧唯一索引、不删除多次取消重约历史、不清空共享 Redis。保留升级后的新增数据并按会员、预约 ID、人数和库存核对。

## 人工验收清单

1. 管理员账号登录、退出、重开恢复；切换到会员/教练身份；Token 过期、撤权、账号停用后不能继续调用。
2. 超过一页的会员列表按手机号/昵称/编号查询；编辑资料、清除有效期、停用/恢复，检查操作记录和旧登录效果。
3. 新建课程、分类、教练和教室；指派课程资格；按名称新建排课，验证无资格、重叠、容量非法时拒绝。
4. 代预约团课与私教，不要求课包；搜索预约、筛选日期/状态，取消、多次重约、返回刷新。
5. 调整到有空位的课；再验证满班/每日限额失败时原预约不丢失；双击或旧 bookingId 重试不改变后续预约。
6. 预约达到容量后缩容拒绝，扩容后名额可用；整节取消成功后会员端刷新状态和原因一致；已有签到时取消拒绝。
7. 签到窗口前/内/后测试代签到、重复签到；核对出勤只有一条，旧预约不能签到新预约。
8. 课程上下架、资源停用、资格撤销及恢复；会员端刷新后可约原因、余位一致。
9. 规则更改后预约判断更新；操作日志可查询修改前后值；店长、前台、教练不能越权。
10. 门店资料、Banner、热门课程、教练团队保存后，会员首页及关于页面刷新一致；断网后失败提示、重试可用。
11. Asia/Shanghai 周一/周日、跨月/跨年及截止时刻显示；管理页大字体、键盘遮挡、长列表、上传和返回刷新分别在开发者工具、iOS、Android 记录结果。

每项记录设备、环境、操作者角色、预期、实际及证据。未实际完成的项目保持待验证；不以浏览器、Node 或编译器结果代替真机通过。
