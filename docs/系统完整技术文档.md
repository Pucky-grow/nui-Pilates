## 1. 项目概述

「优仪普拉提」是一套面向普拉提工作室的数字化运营系统，覆盖从获客、约课、支付、训练到营销统计的完整商业闭环。

| 端 | 技术栈 | 服务对象 |
|---|---|---|
| 微信小程序（用户端 + 教练端） | 原生小程序（WXML/WXSS/JS） | 学员、教练 |
| Web 管理后台 | Vue 3 + Vite + Element Plus + Pinia + ECharts | 管理员、店长、前台、教练 |
| Java 后端 | Spring Boot 3.2 + MyBatis-Plus + MySQL 8 + Redis + Redisson | 三端共用 |

### 技术要点
- **模块化单体 + DDD 分层**（interfaces → application → domain → infrastructure）
- **事件驱动**：`EventPublisher` 抽象，dev=内存事件总线，prod=RocketMQ（`yoyi.mq.type` 切换）
- **微信登录/支付 V3** 全流程 + `mock-login`/`mock-enabled` 开发开关
- **登录保持**：小程序 token 2 小时超时自动退出重新登录
- 品牌视觉：米白/奶油/鼠尾草绿，高级简洁女性化

## 4. 数据库设计（52 张表）

### 4.1 表分类
- **用户会员**(4)：`user`、`user_profile`、`member`、`member_level`
- **教练课程**(10)：`coach`(含openid)、`coach_certificate`、`course`、`course_category`、`classroom`、`course_schedule`、`course_coach`(课程↔教练多对多)、`course_proposal`(课程方案)、`course_version`(版本)
- **预约签到**(3)：`booking`、`attendance`、`waitlist`(候补)
- **课包**(4)：`package`、`package_item`、`user_package`、`package_credit_log`
- **交易**(4)：`order`、`order_item`、`payment`、`refund`
- **营销**(4)：`coupon`、`user_coupon`、`points_record`、`invitation`
- **训练评估**(4)：`training_record`、`body_assessment`、`body_measurement`、`course_review`、`training_record_template`
- **内容**(5)：`article`、`article_category`、`article_like`、`article_favorite`、`banner`
- **消息**(2)：`notification`、`notification_template`
- **教练运营**(4)：`coach_leave`(请假)、`schedule_change_request`(调课)、`coach_availability`(可预约时间)、`feedback`(意见反馈)
- **系统**(8)：`sys_user`、`sys_role`、`sys_permission`、`sys_user_role`、`sys_role_permission`、`operation_log`、`system_config`、`user_privacy`

### 4.2 关键约定
- 通用字段：`id/created_at/updated_at/deleted`（逻辑删除）
- 金额 `DECIMAL(10,2)`；状态用 VARCHAR 枚举
- **幂等唯一索引**：`booking(user_id,schedule_id,deleted)`、`order.order_no`、`payment.out_trade_no`、`user_package(order_id,package_id)`、`attendance.booking_id`、`course_review.booking_id`、`waitlist(schedule_id,user_id)`、`course_coach(course_id,coach_id)`
- **防超扣条件 UPDATE**：`course_schedule(booked_count<max)`、`user_package(remaining>=N)`、`order(PENDING→PAID)`、`payment(PENDING→SUCCESS)`、`coupon(库存)`、`user_coupon(UNUSED→USED)`
- 业务规则走 `system_config` 表（预约/取消/积分规则等，后台可改）

## 5. 核心业务流程与机制

### 5.1 预约（高并发防超卖，四道防线）
`@Idempotent`(Redis SETNX) → Redisson 分布式锁 → Redis DECR 预占 → DB 事务（排课条件UPDATE占座 + 唯一索引 + 课时条件扣减 + 流水）。失败回补库存。

### 5.2 微信支付（回调幂等，四道防线）
`payment.out_trade_no` 唯一 → `payment` 乐观推进 → `order` 乐观推进 → `user_package(order_id,package_id)` 唯一防重复发课包。

### 5.3 课包课时
一切课时变动 = 条件 UPDATE + `package_credit_log` 流水（可对账）。余额=流水累计。

### 5.4 候补
满员加入 → 有人取消 → 队首自动转正（生成预约+扣课时，`WaitlistConsumer` 监听取消事件）。

### 5.5 课程申请审核（Phase 5）
教练创建方案(DRAFT) → 提交(PENDING_REVIEW) → 店长审核 → 通过则生成正式课程 + `course_coach`(APPROVED) 授课资格；排课校验「课程上架 + 教练有授课资格」。

### 5.6 邀请奖励
新用户绑定邀请码 → 首购(ORDER_PAID) → 邀请人自动得积分（幂等）。

### 5.7 定时任务（PilatesScheduler）
关超时单/课程自动完成+爽约/开课提醒/会员到期+课时不足提醒/过期课包/Redis库存对账。

## 7. 部署与环境配置

### 7.1 目录结构
```
plates/
├─ miniprogram/   小程序（27 主包 + 10 教练端分包 + assets）
├─ server/        Spring Boot 后端（18 模块）
├─ admin/         Vue3 管理后台（15 视图）

├─ deploy/        docker-compose + Dockerfile×2 + nginx.conf

```

### 7.2 启动方式
```bash
# 数据库（首次）
mysql -uroot -p < database/schema.sql && mysql -uroot -p < database/init_data.sql
# 后端（mock 模式）
cd server && MYSQL_PASSWORD=xxx SERVER_PORT=8090 java -jar target/pilates-server.jar
# 管理后台
cd admin && npm install && npm run dev   # http://localhost:5173
# 小程序：开发者工具导入 miniprogram/
```

### 7.3 关键配置（application.yml）
- `yoyi.wx.mock-login`：mock 登录开关
- `yoyi.pay.mock-enabled`：mock 支付开关
- `yoyi.mq.type`：memory / rocketmq
- `yoyi.jwt.mp-ttl`：小程序 token 有效期（7200000 = 2 小时）
- 敏感信息全部环境变量注入（WX_APPID/WX_SECRET/WX_PAY_*/MYSQL_*/REDIS_*/ROCKETMQ_NAMESRV/JWT_SECRET）

### 7.4 Docker 部署
`cd deploy && docker compose up -d`（MySQL/Redis/RocketMQ/server/admin/nginx）

## 9. 维护与更新注意事项

### 9.1 代码约定
1. **统一响应** `Result{code,message,data}`，0=成功；异常抛 `BusinessException(ResultCode)`
2. **事务陷阱**：`@Transactional` 方法被同类自调用会失效 → 事务方法放独立 Bean（参照 `BookingTxService`）
3. **数据权限必须后端实现**，不依赖前端隐藏按钮（`requireCoach()` + coachId 强制）
4. **敏感操作加 `@OpLog`**（调课时/退款/审核/改排课等）
5. **幂等操作**：预约/支付回调/签到/领券/候补转正/邀请奖励/新人礼包

### 9.2 数据库变更流程
1. 修改 `database/schema.sql`（并注意 H2 索引名需全局唯一）
2. 生成 `migration_*.sql`（幂等，供已部署库增量升级）
3. 重新生成 H2 测试 schema：
```bash
sed -E -e '/^CREATE DATABASE/d' -e '/^USE /d' -e '/^SET NAMES/d' -e '/^  DEFAULT CHARACTER SET/d' -e "s/\) ENGINE=InnoDB COMMENT='[^']*';/);/" database/schema.sql > server/src/test/resources/schema-h2.sql
```

### 9.3 遗留项（可继续完善）
- Phase 8 全面测试（权限越权测试清单、并发回归）
- 邀请海报/分享链接（当前仅邀请码）
- 会员等级自动升降级（当前等级靠后台手动调整）
- 部分退款、课程版本管理 UI（表已建）
- Dashboard 的 ECharts chunk 体积优化（按需引入）

### 9.4 文案规范
健康/产后内容不做医疗诊断，统一用「训练/改善/体态管理/身体状态/运动建议」，避免「治疗/治愈/根治/医疗诊断」。
